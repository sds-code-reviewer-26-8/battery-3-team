# code-explainer-html

소스코드를 읽고, 신입 팀원이 30분 안에 전체 그림을 잡을 수 있는 **자체 완결형 HTML 한 장**을 만든다.

## 원칙
- **코드를 먼저 읽는다.** 추측으로 쓰지 않는다. 설명에 나오는 클래스·메서드·파일명은 실제 존재하는 것만 쓴다.
- **쉬운 말로 쓴다.** 전문 용어는 처음 나올 때 한 줄로 풀어 준다.
- **"무엇"보다 "왜"를 쓴다.** 구조가 왜 그렇게 나뉘었는지, 이 값을 왜 이렇게 검사하는지를 설명한다.
- 코드에 없는 것은 쓰지 않는다. 확신이 없으면 "코드만으로는 알 수 없음"이라고 적는다.

## 절차
1. **파악**: 빌드 파일(`build.gradle*`, `pom.xml`, `package.json` 등), 설정 파일, 진입점, 패키지 구조, 테스트를 훑는다. 줄 수가 큰 파일이 보통 핵심이다.
2. **핵심 읽기**: 서비스/도메인 로직과 가장 큰 파일은 전체를 읽는다. 컨트롤러, 엔티티, 설정은 역할 위주로 읽는다.
3. **정리**: 아래 구성에 맞춰 내용을 정리한다.
4. **HTML 작성**: 하나의 `.html` 파일로 저장한다. 저장 위치는 사용자가 지정한 경로를 따르고, 없으면 `docs/understand/<이름>/` 아래에 둔다.
5. **확인**: 파일이 생성됐는지, 언급한 이름이 실제 코드와 일치하는지 다시 확인한다.

## HTML 구성 (이 순서)
1. **한 줄 요약**: 이 프로젝트가 무엇을 하는지.
2. **기술 스택**: 언어, 프레임워크, DB. 빌드 파일에서 확인한 값만.
3. **구조도 (인터랙티브)**: 계층 또는 패키지 관계를 인라인 SVG로 그린다. 화살표는 호출 방향. 아래 "인터랙션 규칙"을 따른다.
4. **핵심 흐름 1~3개 (인터랙티브)**: 사용자 행동 하나를 따라가며 단계별로 설명한다. 각 단계에 담당 파일/메서드를 붙인다. 그림 위에서 단계를 하나씩 재생할 수 있게 한다.
5. **핵심 개념 용어집**: 도메인 용어, 주요 클래스의 역할.
6. **가장 어려운 부분**: 가장 복잡한 로직을 규칙 → 단계 순으로 푼다.
7. **알아 둘 점**: 보안 가정, 성능 한계, 하드코딩 같은 주의사항.
8. **파일 지도**: 파일별 한 줄 설명 표.

## 인터랙션 규칙 (그림)
그림은 장식이 아니라 **실제 코드 구조와 흐름을 보여 주는 것**이어야 한다. 노드와 화살표는 코드에서 확인한 것만 그린다.

- **구조도**
  - 노드(계층·패키지·클래스)를 클릭하면 옆 패널에 역할, 주요 메서드, 파일 경로를 보여 준다.
  - 노드에 마우스를 올리면 연결된 화살표와 노드를 강조하고 나머지는 흐리게 한다.
- **흐름 재생**
  - "다음 / 이전 / 처음부터" 버튼으로 단계를 하나씩 진행한다.
  - 현재 단계의 노드와 화살표를 강조하고, 단계 설명과 담당 파일/메서드를 함께 표시한다.
  - 데이터가 이동하는 것을 점이나 토큰으로 화살표를 따라 움직여 보여 준다.
- **값을 바꿔 보는 미니 데모**(선택): 핵심 로직이 입력에 따라 달라지면, 입력을 바꿨을 때 결과가 어떻게 달라지는지 간단한 계산을 JS로 재현한다. 재현한 규칙은 코드와 동일해야 하며, 단순화했다면 그 사실을 표기한다.
- 키보드로도 조작 가능하게 한다(Tab 포커스, Enter/Space로 선택, 좌우 방향키로 이전/다음).
- 애니메이션은 `prefers-reduced-motion` 설정 시 끈다.
- 색만으로 구분하지 않고 라벨과 모양도 함께 쓴다.

## HTML 작성 규칙
- 외부 라이브러리·CDN·이미지 없이 **파일 하나로 열리게** 한다. CSS와 JS는 인라인. 인터랙션도 순수 JS와 SVG로 구현한다.
- 라이트/다크 모드 모두 읽히도록 색을 CSS 변수로 정의한다.
- 모바일 폭에서도 가로 스크롤이 생기지 않게 한다.
- 긴 코드는 넣지 않는다. 핵심 몇 줄만 `<pre>`로 인용하고 파일 경로와 함께 표기한다.
- 목차(앵커 링크)를 상단에 둔다.
- 한국어로 작성한다(사용자가 다른 언어를 요청하면 그 언어).

## 하지 말 것
- 코드를 읽지 않고 일반론으로 채우지 않는다.
- 모든 파일을 나열하느라 핵심 흐름이 묻히게 하지 않는다. 파일 지도는 8번 한 곳에만 둔다.
- 사용자가 요청하지 않은 코드 수정, 커밋, push를 하지 않는다.
