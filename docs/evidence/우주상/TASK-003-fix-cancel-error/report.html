0반복 횟수

한 줄 요약: 취소 후 삭제된 주문을 다시 조회하지 않고 같은 화면에 안내를 보여 주도록 고쳐 에러 페이지(HTTP 500)가 사라졌다. 없는 주문의 화면도 500 대신 안내를 보여 준다. JUnit 35/35, E2E 78 통과(건너뜀 1개는 깨끗한 DB에서 통과), 전체 3회 반복에서도 실패 0. 처음 검증에서 통과해 되돌아간 반복은 없다.

※ 위 숫자는 3장 표(id="results")의 행만 센다. 표 밖의 건너뜀·미확인은 집계되지 않으므로 5장을 함께 읽는다. "건너뜀·미확인 0"을 "문제 없음"으로 읽지 않는다.

2구현 요약

구현한 것① 취소하면 주문이 삭제된 뒤 같은 화면에 "주문 #N을(를) 취소했습니다. 취소한 주문은 삭제되어 목록에서 사라집니다." 안내와 "목록으로" 버튼이 보인다(더 이상 삭제된 주문의 상세 주소로 이동하지 않는다). ② 없는 주문 번호의 화면 주소(/orders/{id})는 500 대신 화면을 열고 "주문을 찾을 수 없습니다" 안내를 보여 준다(JSON API는 404 그대로). ③ 취소가 충돌 등으로 실패하면 이유를 보여 주고 최신 상태를 다시 불러온다.
접근 방법사전 검토의 대안 A. 취소 API가 이미 돌려주는 deleted:true를 화면이 받아 처리하게 하고, 화면 주소가 주문 존재를 확인하던 부분을 없애 안내를 화면에 맡긴다. 서비스(업무 규칙)는 바꾸지 않았다.
