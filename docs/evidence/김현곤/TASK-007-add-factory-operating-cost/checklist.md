# checklist — TASK-007-add-factory-operating-cost
리뷰 수준: Red — 계산(Planner)·기준 정보·주문 저장·화면·PRD 에 걸친 거대한 변경이고 6원칙 중 5개가 "주의"

## 6원칙 판정
| # | 원칙 | 판정 | 근거 |
|---|---|---|---|
| 1 | 확정은 서버가 다시 계산 | 주의 | 운영비·총비용도 confirm() 의 서버 재계산 결과로만 저장해야 함 |
| 2 | 확정한 주문은 불변 | 주의 | Order/StoredPlan 에 운영비 추가, 기존 주문은 "-" 표시하되 금액·날짜 유지 필요 |
| 3 | 기준 변경 시 masterVersion | 주의 | 공장별 운영비는 새 기준 정보 항목, updateMaster 경로에서 버전을 올려야 함 |
| 4 | 상태 변경 동시 수정 확인 | 영향 없음 | changeStatus 경로를 건드리지 않음 |
| 5 | 전부 맞아야 저장 | 주의 | 운영비 입력 검사 추가, 일괄 검증·전부 저장 안 함 유지 필요 |
| 6 | 검산(simulateFactory) 유지 | 주의 | 비용 최소 선택 기준 변경 시 일정 계산·검산을 건드리지 않아야 함 |

## 체크리스트 (구현 종료 후 반드시 확인)
- [ ] CK-1 운영비 계산·선택: PlannerTest 로 운영비 = 주문 있는 공장 수 × 공장별 일 운영비 × totalDays(주문 0 공장 0원), 총비용 = 생산비+운항비+운영비, "비용 최소"(label 변경)는 운항비+운영비 최소, FAST/NEAR 선택 기준 불변, simulateFactory 유지를 단언하는 테스트가 통과
- [ ] CK-2 기준 정보: master 화면/API 에서 공장별 일 운영비(억 원 소수 입력, 기본 1억)를 저장하면 masterVersion 이 오르고, 잘못된 값이 하나라도 있으면 전부 저장 안 됨 — 통합 테스트로 확인
- [ ] CK-3 확정·과거 주문: 확정 시 운영비가 서버 재계산값으로 Order·StoredPlan 에 저장되고 화면(주문 추가·상세·목록)에 표시됨, 운영비 없는 과거 주문(JSON/컬럼 null)은 "-" 로 열리며 기존 금액·날짜 불변 — 통합 테스트로 확인
