## 관찰 사항

- **DTL-08** `GET /orders/999999` 가 HTTP 500 을 응답했습니다. `BatteryService.getOrder` 가 던진 업무 오류를 화면 요청에서는 컨트롤러가 처리하지 않기 때문으로 보입니다(PRD '결함 후보'와 일치).
- **DTL-05** 확정 주문을 취소하면 주문이 삭제된 뒤 삭제된 주문의 상세(`/orders/{id}`)로 이동하며 이 이동이 HTTP 500 입니다. 취소 자체(주문 삭제)는 DTL-06 에서 확인했습니다.
- **DTL-06** 취소한 주문은 목록에서 사라지고 '취소' 칩 건수는 0 으로 유지됩니다. 취소 주문을 보관·조회해야 하는지는 PRD 열린 질문(취소 시 주문 삭제)에서 팀이 정해야 합니다.
- **CNF-06 / DTL-07** 브라우저 컨텍스트 두 개(서로 다른 세션)로 동시 변경과 마스터 변경 충돌을 재현했고, 서버가 거부 메시지를 내는 것을 확인했습니다.
- DTL-05, DTL-08 은 `test.fail()` 로 '알려진 결함' 표시를 했습니다. 결함이 고쳐지면 "실패로 표시했는데 통과했다"고 알려 주므로, 그때 `test.fail` 줄을 지우면 됩니다.

## 다시 실행하는 방법

```
cd e2e
npm install
npx playwright install chromium   # 처음 한 번
npx playwright test order-confirm order-detail
```

서버를 직접 띄우지 않아도 됩니다(별도 포트에 인메모리 서버를 자동 실행). 이미 떠 있는 서버를 쓰려면 `BASE_URL=http://localhost:8080` 을 지정하세요. 이때 테스트가 주문을 만들고 마스터 버전을 올리므로 개발 데이터가 바뀝니다.

원본 데이터는 `e2e/results/cnf-dtl-headless-run.json` 입니다.
